# Hydra TxPool Operator Blacklist (sample / template)
#
# Copy this file to /opt/hydra-blacklist.txt on your validator host (or set
# HYDRA_TX_BLACKLIST_FILE=/path/to/file in the node's environment) to
# activate it. The hydra binary auto-loads it on startup and re-reads it
# every 5 seconds on mtime change — no validator restart required when
# adding or removing addresses.
#
# This file is OPTIONAL. The hydra binary embeds a baseline blacklist at
# build time (see txpool/baseline_blacklist.txt) which already covers the
# bridge attacker wallet on every node. Entries listed here are ADDITIVE
# on top of that baseline. Removing an address from this file does NOT
# unblock baseline entries.
#
# Format: one address per line, '#' for whole-line and inline comments,
# blank lines ignored, addresses case-insensitive. Malformed lines are
# silently skipped. Set is bounded to 100k entries.
#
# Behavior: any transaction whose recovered sender appears in the
# (baseline ∪ this file) set is refused admission to the local txpool.
# This is a pool-only check, NOT a consensus rule — partial rollout
# across the validator set is safe.
#
# To clear an entry: comment out or remove its line; the node picks up
# the change within ~5s. Do NOT delete the entire file — that's treated
# as a transient I/O failure and the in-memory union is preserved on
# purpose. To clear all entries, leave the file containing only comments
# and blanks.
#

# filter is active on their node by attempting a transaction from each
